# Product Constitution

Version: 1.0

This document defines the permanent principles of CrossPort.

These principles take priority over feature requests, implementation convenience, and short-term trends.

---

# Rule 1

Protect user data above everything.

No feature is worth risking user files.

---

# Rule 2

Offline First.

Core functionality must never require internet access.

---

# Rule 3

Beginner First.

Complexity must remain hidden unless explicitly requested.

---

# Rule 4

Advanced Mode.

Power users may unlock additional functionality without making the default experience more difficult.

---

# Rule 5

Friendly Communication.

Every message should explain:

- What happened.
- Why it happened.
- What the user should do next.

---

# Rule 6

Performance is a Feature.

Responsiveness is part of the product.

---

# Rule 7

No Artificial Limits.

CrossPort should never impose unnecessary limits on transfer size, file count, or project scale.

Only operating system limitations should apply.

---

# Rule 8

User Control.

Users decide:

- Updates
- Verification
- History retention
- Advanced settings

---

# Rule 9

One Purpose.

CrossPort exists to simplify cross-platform file movement.

Features outside this mission require exceptional justification.

---

# Rule 10

Quality Before Quantity.

Every feature must improve the recommendation factor.

Feature count is never a success metric.

---

# Rule 11

Transparency.

CrossPort should never perform hidden actions affecting user files.

---

# Rule 12

Professional Standards.

Every release should improve:

- Stability
- Reliability
- Simplicity
- User confidence

---

# Rule 13

Architecture Before Implementation.

Every significant feature requires a documented specification before development begins.

---

# Rule 14

Consistency.

Every interaction should behave predictably across Windows, macOS, and Linux.

---

# Rule 15

Long-Term Thinking.

Architecture decisions should minimize future rewrites and preserve maintainability.
